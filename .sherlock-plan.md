# Sherlock Plan: AI Autonomy Selector

Created: 2026-04-05
Tier: Full Sherlock
Status: APPROVED — Ready for Holmes

## Summary
Add a 3-level AI autonomy selector to the Action Center that controls how much the AI can do without human intervention. Levels: Suggest Only (1), Auto-Approve + Confirm Execute (2), Full Autonomous (3).

## Architecture Decision

### Approach Chosen: Hybrid (Option C)
- **At creation time:** autonomyLevel 2+ auto-sets high/medium priority actions to "approved"
- **At execution time:** cron checks autonomyLevel to decide CIBA vs direct execute
- **Safety net:** Level 3 skips CIBA for routine actions but retains CIBA for >$50K deals
- **Low priority:** Always starts as "pending" regardless of autonomy level
- **Confirmation dialog:** Required when user selects level 3

### Rationale
- Immediate visual feedback (approved badge shows autonomy is working)
- Strong security story (graduated trust with high-value safety net)
- Great demo moment ("4 auto-executed, 1 Guardian push for $75K deal")
- Backward compatible (level 1 = current behavior, zero regression risk)

### Rejected Alternatives
- **Option A (creation-only):** Insufficient — doesn't handle execution-time branching for CIBA vs direct
- **Option B (execution-only):** Actions show as "pending" under full autonomy until cron tick — confusing UI

## Status Flow Per Level
```
Level 1: pending → [user approves] → approved → [user executes / CIBA] → sent
Level 2: approved (auto) → [CIBA batch push] → [phone approve] → executing → sent
Level 3: approved (auto) → executing → sent  (routine, <$50K)
Level 3: approved (auto) → [CIBA push] → [phone approve] → executing → sent  (>$50K)
```

## Acceptance Criteria

### AC-1: Default behavior unchanged
**Given** a user with no autonomyLevel set (default = 1)
**When** actions are created via AI pipeline analysis
**Then** all actions start with status "pending"

### AC-2: Level 2 auto-approves at creation
**Given** a user with autonomyLevel = 2
**When** the AI creates high/medium priority actions
**Then** those actions start with status "approved"

### AC-3: Level 2 still requires CIBA for execution
**Given** a user with autonomyLevel = 2 and approved actions
**When** the scheduled batch runs (or Run Now triggered)
**Then** CIBA is initiated and Guardian push sent before execution

### AC-4: Level 3 auto-executes without CIBA (routine)
**Given** a user with autonomyLevel = 3 and approved actions linked to deals under $50K
**When** the scheduled batch runs
**Then** actions execute directly without CIBA consent

### AC-5: Level 3 retains CIBA for high-value deals
**Given** a user with autonomyLevel = 3 and an action linked to a >$50K deal
**When** the scheduled batch runs
**Then** CIBA is still initiated for that action

### AC-6: Low priority excluded from auto-approve
**Given** a user with autonomyLevel = 2 or 3
**When** the AI creates a low priority action
**Then** it starts with status "pending" regardless of autonomy level

### AC-7: Settings persistence
**Given** a user changes autonomyLevel in the UI
**When** the setting is saved via PUT /api/settings
**Then** it persists in Redis and is reflected on page reload

### AC-8: UI selector matches design system
**Given** the actions page
**When** the user views the SchedulePanel
**Then** a 3-level segmented control is visible using the existing button group pattern

### AC-9: Level 3 confirmation dialog
**Given** a user selects autonomy level 3
**When** the selection is made
**Then** a confirmation dialog appears warning that AI will execute routine actions without asking
**And** the level only changes if the user confirms
