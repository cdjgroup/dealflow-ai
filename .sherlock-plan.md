# Sherlock Plan: Per-Client MCP Policy System

Created: 2026-04-05
Tier: Full Sherlock
Status: PLANNING — Awaiting Approval

## Context

The app has three surfaces (Chat, Actions, MCP) with implicit trust levels but no explicit policy engine. MCP gives every authenticated client the same read-only tools with no differentiation. The audit log can't distinguish which surface a tool call came from. Web research confirmed: per-client tool filtering is entirely custom — not in MCP spec, mcp-handler, or Auth0 docs.

## Scope Boundaries

- IN SCOPE:
  - Surface policy registry (formal declarations for chat/mcp/actions)
  - Per-client MCP policies (tool allowlists per client)
  - API key generation, hashing, rotation for MCP clients
  - Dual auth in MCP route (API key + Auth0 bearer)
  - Per-client tool filtering in MCP tool handler
  - Trust tier labels + client management UI on MCP Explorer
  - Source filter on audit log (chat/mcp/actions)
  - Per-client rate limiting
  - Per-client usage analytics
- OUT OF SCOPE:
  - Per-client `tools/list` filtering (mcp-handler registers tools statically; filtering happens at `tools/call` time — document as known limitation)
  - Auth0 M2M client registration (too heavy for hackathon)
  - Write-tool exposure via MCP (approval UI doesn't exist in MCP protocol)
  - Capability toggle enforcement in MCP (separate bug fix, not part of this plan)

## Architecture Decision

Approach chosen: Clean
Summary: Full per-client API key system with Redis-backed policies, dual auth, trust tiers, rate limiting, and analytics. Custom implementation since no spec-supported path exists.
Rationale: Research confirmed per-client tool filtering is not in the MCP spec (2025-03-26), mcp-handler v1.1.0, or Auth0 MCP docs. The only viable approach is custom API key management with policy lookup at tool-call time. The `mcp-handler` library's `AuthInfo.extra` field provides the extensibility hook — we populate it with client policy metadata in `verifyToken` and read it in tool handlers. This is the cleanest design that reuses existing infrastructure (Redis CRUD from actions.ts, rate-limit.ts factory pattern, crypto.ts for hashing).

## Acceptance Criteria

### AC-1: API key generation produces unique, prefixed keys
- **Given** `generateApiKey()` is called
- **When** the result is inspected
- **Then** `raw` starts with `dfk_`, is ~47 chars, and `hashApiKey(raw) === hash`

### AC-2: API key generation is non-deterministic
- **Given** `generateApiKey()` is called twice
- **When** results are compared
- **Then** raw keys and hashes differ

### AC-3: MCP client CRUD lifecycle
- **Given** a user creates an MCP client with name "Research Bot" and allowedTools ["listDeals", "searchContacts"]
- **When** `listMcpClients(userId)` is called
- **Then** the client appears with correct name, tools, and a valid apiKeyHash

### AC-4: API key reverse lookup
- **Given** a client was created and the raw API key was returned
- **When** `lookupByApiKey(rawKey)` is called
- **Then** it returns `{ userId, clientId }` matching the creator

### AC-5: API key rotation invalidates old key
- **Given** a client exists with API key A
- **When** `rotateApiKey(userId, clientId)` is called
- **Then** `lookupByApiKey(oldKey)` returns null AND `lookupByApiKey(newKey)` returns the correct client

### AC-6: Client deletion removes API key
- **Given** a client exists
- **When** `deleteMcpClient(userId, clientId)` is called
- **Then** `lookupByApiKey(rawKey)` returns null AND `getMcpClient` returns null

### AC-7: Dual auth — API key path
- **Given** a valid `dfk_` API key for client "Bot-A" with allowedTools ["listDeals"]
- **When** an MCP request uses this key as bearer token
- **Then** `authInfo.extra.mcpClientId` equals the client ID and `authInfo.extra.allowedTools` equals ["listDeals"]

### AC-8: Dual auth — invalid API key
- **Given** an invalid `dfk_xxx` string
- **When** used as MCP bearer token
- **Then** 401 Unauthorized is returned

### AC-9: Dual auth — Auth0 token backward compatibility
- **Given** a valid Auth0 access token (not prefixed `dfk_`)
- **When** used as MCP bearer token
- **Then** behavior is unchanged — `authInfo.extra.mcpClientId` equals "default"

### AC-10: Per-client tool filtering — allowed tool
- **Given** client with allowedTools ["listDeals"]
- **When** it calls `listDeals` via MCP
- **Then** execution succeeds normally

### AC-11: Per-client tool filtering — disallowed tool
- **Given** client with allowedTools ["listDeals"]
- **When** it calls `checkCalendar` via MCP
- **Then** returns `{ error: "Tool not available for this client", isError: true }`

### AC-12: Default client gets all MCP-safe tools
- **Given** an Auth0 bearer token (no API key)
- **When** any MCP-safe tool is called
- **Then** execution proceeds (no allowlist check)

### AC-13: Per-client rate limiting
- **Given** a client with rateLimit of 2 per minute
- **When** 3 requests are made within 1 minute
- **Then** the 3rd returns a rate limit error

### AC-14: Rate limit independence
- **Given** two clients A and B each with rateLimit 2
- **When** A exhausts its limit
- **Then** B can still make requests

### AC-15: Audit entries include surface tag
- **Given** a tool call via chat
- **When** the audit entry is written
- **Then** `surface === "chat"`

### AC-16: Audit entries include MCP client ID
- **Given** a tool call via MCP with client "Bot-A"
- **When** the audit entry is written
- **Then** `surface === "mcp"` AND `mcpClientId` equals the client ID

### AC-17: Audit source filter
- **Given** audit entries from chat, MCP, and actions
- **When** the audit API is called with `?surface=mcp`
- **Then** only MCP entries are returned

### AC-18: Analytics recording
- **Given** 5 successful and 2 failed MCP calls for client "Bot-A"
- **When** `getMcpAnalytics(userId, clientId)` is called
- **Then** totalCalls=7, successCount=5, errorCount=2

### AC-19: Client management API — auth required
- **Given** an unauthenticated request
- **When** `GET /api/mcp/clients` is called
- **Then** 401 is returned

### AC-20: Client management API — CSRF on mutations
- **Given** a POST without `X-Requested-With` header
- **When** creating a client
- **Then** 403 is returned

### AC-21: Client management API — create returns raw key once
- **Given** valid input
- **When** `POST /api/mcp/clients` is called
- **Then** 201 with `{ client, rawApiKey }` — raw key in response body

### AC-22: Surface policy registry
- **Given** surface "mcp"
- **When** `getSurfacePolicy("mcp")` is called
- **Then** returns policy with `requiresApproval: false`, `requiresCiba: false`

### AC-23: Trust tier tool defaults
- **Given** trust tier "restricted"
- **When** creating a client with that tier
- **Then** allowedTools defaults to CRM read + calendar + email (not slack)

### AC-24: MCP Explorer shows client cards
- **Given** a user with 2 MCP clients
- **When** visiting /dashboard/mcp
- **Then** both client cards render with correct trust tier badges and tool lists

### AC-25: MCP Explorer — create client flow
- **Given** user clicks "Create Client" and fills the form
- **When** form is submitted
- **Then** new card appears and raw API key is shown in a copyable one-time dialog

## Interface Contracts

```typescript
// ===== src/lib/types/policy.ts =====

export type Surface = "chat" | "mcp" | "actions";
export type TrustTier = "full" | "standard" | "restricted" | "readonly";

export interface SurfacePolicy {
  surface: Surface;
  allowedToolCategories: string[];
  requiresApproval: boolean;
  requiresCiba: boolean;
}

export interface McpClient {
  id: string;
  userId: string;
  name: string;
  description?: string;
  allowedTools: string[];
  trustTier: TrustTier;
  rateLimit: number;              // requests per minute
  apiKeyHash: string;
  apiKeyPrefix: string;           // first 8 chars for display
  createdAt: string;
  updatedAt: string;
  lastUsedAt?: string;
}

export interface McpClientCreateInput {
  name: string;
  description?: string;
  allowedTools?: string[];        // defaults from trustTier if omitted
  trustTier?: TrustTier;          // defaults to "standard"
  rateLimit?: number;             // defaults to 60
}

// ===== src/lib/crypto.ts (additions) =====

export function generateApiKey(): { raw: string; hash: string; prefix: string };
export function hashApiKey(raw: string): string;

// ===== src/lib/data/mcp-clients.ts =====

export function createMcpClient(userId: string, input: McpClientCreateInput): Promise<{ client: McpClient; rawApiKey: string }>;
export function getMcpClient(userId: string, clientId: string): Promise<McpClient | null>;
export function listMcpClients(userId: string): Promise<McpClient[]>;
export function updateMcpClient(userId: string, clientId: string, data: Partial<Pick<McpClient, "name" | "description" | "allowedTools" | "trustTier" | "rateLimit">>): Promise<McpClient | null>;
export function deleteMcpClient(userId: string, clientId: string): Promise<boolean>;
export function rotateApiKey(userId: string, clientId: string): Promise<{ client: McpClient; rawApiKey: string } | null>;
export function lookupByApiKey(rawKey: string): Promise<{ userId: string; clientId: string } | null>;

// ===== src/lib/data/mcp-analytics.ts =====

export interface McpAnalyticsSummary {
  totalCalls: number;
  successCount: number;
  errorCount: number;
  successRate: number;
  topTools: { name: string; count: number }[];
  dailyBreakdown: { date: string; calls: number; success: number }[];
}

export function recordMcpCall(userId: string, clientId: string, toolName: string, success: boolean): Promise<void>;
export function getMcpAnalytics(userId: string, clientId: string, days?: number): Promise<McpAnalyticsSummary>;

// ===== src/lib/policy/surface-policy.ts =====

export function getSurfacePolicy(surface: Surface): SurfacePolicy;

// ===== src/lib/rate-limit.ts (addition) =====

export function getMcpClientLimiter(clientId: string, requestsPerMinute: number): Ratelimit;

// ===== API Routes =====

// GET  /api/mcp/clients                          → McpClient[]
// POST /api/mcp/clients                          → { client: McpClient; rawApiKey: string }
//   Body: McpClientCreateInput
// GET  /api/mcp/clients/[clientId]                → McpClient
// PUT  /api/mcp/clients/[clientId]                → McpClient
//   Body: Partial<McpClientCreateInput>
// DELETE /api/mcp/clients/[clientId]              → { success: boolean }
// POST /api/mcp/clients/[clientId]/rotate-key     → { client: McpClient; rawApiKey: string }
// GET  /api/mcp/clients/[clientId]/analytics      → McpAnalyticsSummary
//   Query: ?days=7

// ===== src/lib/types/audit.ts (additions) =====

export interface AuditEntry {
  // ...existing fields...
  surface?: Surface;
  mcpClientId?: string;
  mcpClientName?: string;
}

export interface AuditFilters {
  // ...existing fields...
  surface?: Surface;
}

// ===== src/lib/constants/tools.ts (additions) =====

export const MCP_SAFE_TOOLS: Set<string>;
export const TRUST_TIER_TOOLS: Record<TrustTier, string[]>;
```
