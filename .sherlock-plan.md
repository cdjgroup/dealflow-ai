## Scope Boundaries
- IN SCOPE:
  - Replace hardcoded action heuristics with LLM-generated suggestions (Fix 1)
  - Add confidence score to SuggestedAction type (Fix 1)
  - Track per-action-type approval/dismiss stats in Redis (Fix 2)
  - Display trust calibration stats and recommendation in permissions UI (Fix 2)
  - Add confirmation panel before batch approve (Fix 3)
- OUT OF SCOPE:
  - Auto-execution based on trust score (would need CIBA flow changes)
  - Per-deal LLM calls (too slow; using batch single-shot)
  - Trust score affecting scheduled cron execution
  - New test file for action-filters component (pure UI, manual QA)

## Architecture Decision
Approach chosen: Pragmatic
Summary: Single-shot `generateText()` with `Output.object()` (Zod schema) + Haiku for validated structured JSON output, heuristic fallback on failure, simple Redis get-modify-set for trust stats.
Rationale: Haiku is fast enough (~0.5-1.5s) to run inside a tool execution without noticeable delay. The single-shot approach avoids N API calls for N deals. `Output.object()` provides schema-validated output via constrained decoding — the model literally cannot produce tokens that violate the Zod schema. This is the official AI SDK v6 approach (generateObject is deprecated). Trust stats use the simplest possible persistence pattern — race conditions on counters are not a concern at demo scale.

### Research Validation (Step 3)
- **Nested AI calls confirmed**: AI SDK docs document this as the "subagent" pattern — calling `generateText()` inside a tool's `execute` is officially supported. Source: ai-sdk.dev/docs/agents/subagents
- **Output.object() confirmed**: `Output.object({ schema })` available in `ai@^6.0.142`. Verified locally: `Output` has keys `[array, choice, json, object, text]`.
- **Model ID confirmed**: `claude-haiku-4-5-20251001` verified locally — `anthropic()` creates model successfully.
- **Key implementation detail**: Pass `abortSignal` from tool context through to nested `generateText()` call. Set `maxRetries: 1` to avoid timeout risk on Vercel (300s function limit).
- **generateObject() is deprecated** in v6, removed in v7. Use `generateText()` with `output: Output.object()` instead.

### Alternatives Considered
1. **generateObject() with Zod** — Deprecated in AI SDK v6, will be removed in v7. Use `generateText()` + `Output.object()` instead.
2. **Raw JSON text parsing** — No schema enforcement, fragile. `Output.object()` is strictly better.
3. **Per-deal LLM calls** — Better per-deal reasoning but N API calls is unacceptably slow for 5-10 deals.
4. **Adaptive auto-execution** — Trust stats could drive automatic execution, but would require CIBA changes and scope creep.

## Acceptance Criteria

### AC-1: LLM generates personalized action suggestions
- **Given** the user has deals in their pipeline with contacts and activity history
- **When** the `analyzePipeline` tool executes
- **Then** Claude Haiku is called with deal context and returns personalized suggestions with unique justifications, drafted content, and confidence scores (0.0-1.0)

### AC-2: LLM suggestions map to existing action types
- **Given** the LLM returns a JSON array of suggestions
- **When** the suggestions are processed
- **Then** each suggestion has a valid type (email/calendar/slack), priority (high/medium/low), and draft matching the expected schema (EmailDraft/CalendarDraft/SlackDraft)

### AC-3: Heuristic fallback on LLM failure
- **Given** the LLM call fails (network error, malformed JSON, timeout)
- **When** the error is caught
- **Then** the tool falls back to the existing heuristic suggestion logic and returns valid suggestions without exposing the error to the user

### AC-4: Confidence score displayed on action cards
- **Given** an action has a confidence score
- **When** it renders in the Action Center
- **Then** a confidence badge (e.g., "87% confident") appears alongside priority and status badges

### AC-5: Trust stats increment on approval
- **Given** a user approves a pending email action
- **When** the PUT `/api/actions/{id}` completes
- **Then** the trust stats for "email.approved" are incremented by 1 in Redis

### AC-6: Trust stats increment on dismiss
- **Given** a user dismisses a pending calendar action
- **When** the PUT `/api/actions/{id}` completes
- **Then** the trust stats for "calendar.dismissed" are incremented by 1 in Redis

### AC-7: Trust stats increment on batch operations
- **Given** a user batch-approves 3 actions (2 email, 1 slack)
- **When** the POST `/api/actions/batch` completes
- **Then** email.approved increments by 2 and slack.approved increments by 1

### AC-8: Trust stats displayed in permissions UI
- **Given** a user has approval stats (e.g., 12 approved, 2 dismissed for email)
- **When** they visit the permissions page
- **Then** they see "Approved 12/14 suggestions (86%)" under the email tool trust controls

### AC-9: Auto-approve recommendation shown at high trust
- **Given** a user has >80% approval rate for an action type
- **When** the trust level for that tool is NOT already "always"
- **Then** a green hint "Consider auto-approve" appears next to the stats

### AC-10: Batch approve shows confirmation
- **Given** there are 5 pending actions (3 email, 1 calendar, 1 slack)
- **When** the user clicks "Approve All Pending"
- **Then** an inline confirmation panel shows "Approve 5 pending actions? 3 emails, 1 calendar event, 1 Slack message" with Confirm/Cancel buttons

### AC-11: Batch approve confirmation can be cancelled
- **Given** the confirmation panel is shown
- **When** the user clicks "Cancel"
- **Then** the panel closes and no actions are approved

### AC-12: Existing actions without confidence still render
- **Given** older actions exist in Redis without a `confidence` field
- **When** they render in the Action Center
- **Then** no confidence badge is shown and the card renders normally
